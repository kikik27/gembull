# GemBull community experiment plan

Adapted from the supplied StonkRitual v0.2 archive. These are **proposed experiments**, not evidence of users, traction, a token sale, or a real stock reward. The current public experience is a NEAR Testnet ritual and a clearly labeled stock concept simulation.

## Positioning

**The meme runs on rituals.** The demonstrable hook is a daily on-chain check-in that changes token supply only through the published contract rules. A planned second layer would use activity-gated simulated stock allocations; it is not live. Avoid “stock-backed”, guaranteed rewards, equity ownership, or claims that every DEX trade funds a reserve.

## First audience and sequence

1. Invite NEAR Testnet users who can complete the register → receive test GEMBULL → check-in flow. The immediate acceptance gate is one real wallet transaction and a reproducible judge walkthrough.
2. Run a small, opt-in seven-day ritual experiment. Publish the 50-account target and actual outcomes, including misses. A 5-of-7 points metric can be shown as a **proposal/simulation** only until implemented.
3. Show source-separated stock reserve arithmetic only as **SIMULATED**. Publish the assumptions, including routed fee and protected graduation surplus, as proposals rather than real inflows.
4. Reassess a real asset route only after the issuer, custodian, legal rights, geography, and economics decisions in [OPEN_DECISIONS.md](OPEN_DECISIONS.md).

## Metrics

The proposed north-star metric is **Weekly Active Ritual Holders**: accounts with five valid check-ins in the previous seven completed epochs and a minimum balance at a defined snapshot. It is not a current on-chain metric because the points/snapshot layer is unbuilt. For the current Testnet phase, measure wallet connection, registration, funded eligible accounts, first check-ins, duplicate-call rejection, completed epochs, and claim/burn evidence. Keep marketing targets separate from actual counts.

Any public post, hackathon submission, or launch announcement requires the owner's review under the project work protocol.
